# zc5s · 大模型选型方案 · 单机 8× RTX 4090 48GB

> 硬件:**1 台**,8× RTX 4090 48GB(改版)/ 共 **384GB 显存** / x86 / **银河麒麟 V10**
> 用途:blade_agent 智能体系统 —— 写 skill / 调 skill / 代码生成(agentic coding)为核心

---

## 一、结论速览

| 项目 | 结论 |
| ---- | ---- |
| **首选模型** | **MiniMax M2.7**(230B-A10B)⭐ —— agentic coding 专精、激活最低 |
| 权重 | **INT4 ~115GB(TP=4 ×2 副本)** 或 **FP8 ~230GB(TP=8 ×1)** |
| 次选(更强推理) | **Qwen3.5-397B-A17B**(INT4 ~200GB,**单机 TP=8 就装下**) |
| 高吞吐/多模态备选 | Qwen3.5-122B-A10B(INT4 ~68GB,可跑 3–4 副本) |
| 部署架构 | **单机**,按"小 TP + 多副本"避开无 NVLink 的 PCIe 短板 |
| **关键红利** | **✅ 有 FP8**(Ada sm_89)——可用 FP8 权重换质量、FP8 KV 省显存,A40 做不到 |
| **关键短板** | **❌ 无 NVLink,卡间仅 PCIe** → 大 TP 的 all-reduce 会打折 |
| 排除 | ❌ Kimi K2.6(500GB 装不下)、GLM-5.2 / DeepSeek-V4(稀疏内核 sm_89 无) |

## 二、三个决定性约束(先看这个)

### 约束 1:有 FP8 了 —— 这是 4090 相对 A40/A100 的最大红利 ⭐

RTX 4090 是 **Ada Lovelace(sm_89)**,**原生支持 FP8**(E4M3/E5M2 Tensor Core)。这意味着 zc5s 能做两件 xt(A40/Ampere)做不到的事:

- **FP8 权重(W8A8)**:质量介于 INT4 与 BF16 之间、明显优于 INT4,而体积只有 BF16 的一半。**装得下就优先 FP8**。
- **FP8 KV cache**:KV 直接减半,并发/长上下文更宽裕。

> ❗ 仍然**没有 FP4**(那是 Blackwell 的)。所以 NVFP4 权重照样不能用,别下错。

### 约束 2:无 NVLink,卡间只有 PCIe —— 决定"怎么切" ⭐

4090 **没有 NVLink**(Ada 消费/专业卡都砍了),8 张卡之间只能走 **PCIe**。而 TP(张量并行)每层都要 all-reduce:

```
TP 越大 → 每层跨卡通信越多 → 在 PCIe 上打折越狠
```

> **推论:zc5s 上优先"小 TP + 多副本",而不是"8 卡合成一个大 TP"。**
> - **TP=4 ×2 副本 / TP=2 ×4 副本**:副本之间是数据并行(DP),**零跨卡通信**,PCIe 短板影响最小,还自带冗余。
> - **TP=8 ×1**:只有当模型大到必须 8 卡才装下时才用(如 397B),且要现场压测 PCIe 上的通信损耗。

先跑 `nvidia-smi topo -m` 看 8 卡的 PCIe 拓扑:是否同一 root、有没有跨 NUMA,决定 TP 组怎么挑。

### 约束 3:单机 384GB —— 定容量上限

8×48 = **384GB**,单机一个池子(不像 xt 要跨机)。留出 KV 与开销,权重实际可用约 **300GB 上限**:

- INT4:可吃到 ~600B 参数级(但要留 KV,实际甜点 200–400GB 权重)。
- FP8:可吃到 ~300B 参数级 FP8。

## 三、内核红线(和 xt 一致,sm_89 同样出局)

sm_89(Ada)**没有 Hopper 专属的稀疏注意力内核**,所以:

| 注意力类型 | 代表模型 | zc5s(sm_89) |
| ---- | ---- | ---- |
| Lightning / Gated DeltaNet / MLA / 标准注意力 | M2.7、Qwen3.5、DeepSeek-V3.1 | ✅ 能跑 |
| **DSA / CSA / HCA / IndexShare 稀疏注意力** | **GLM-5.2、DeepSeek-V4/V3.2** | ❌ 出局 |

## 四、选型:带宽 + FP8 算给你看

按 `解码速度 ≈ 0.7 × 1008 GB/s ÷ 每卡每token激活读取字节` 估算(**PCIe 上 TP 越大,实测越要打折**):

| 模型 | 激活 | 量化 | 布局 | 装载 | 每卡激活读取 | 理论 tok/s | 结论 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| **MiniMax M2.7** ⭐ | 10B | INT4 | **TP=4 ×2** | 115GB/副本 | 1.25GB | **~560** | ✅ **最优**:快、专精、带冗余、PCIe 友好 |
| MiniMax M2.7 | 10B | **FP8** | TP=8 ×1 | 230GB | 1.25GB | ~560(TP=8 打折) | ✅ 质量最好,但无冗余 + TP=8 |
| **Qwen3.5-397B-A17B** | 17B | INT4 | TP=8 ×1 | ~200GB | 1.06GB | ~660(TP=8 打折明显) | ✅ 通用推理最强,单机装下 |
| Qwen3.5-122B-A10B | 10B | INT4 | TP=2 ×4 | 68GB/副本 | 2.5GB | ~280 | ✅ 高并发 + 多模态,PCIe 最友好 |
| Qwen3.5-122B-A10B | 10B | FP8 | TP=4 ×2 | 136GB/副本 | 5GB | ~140 | ✅ 质量优先的中档 |
| DeepSeek-V3.1 | 37B | INT4 | TP=8 ×1 | ~350GB | 2.3GB | ~305 | ⚠️ 装得下但极紧(几无 KV)、慢、旧 |
| Kimi K2.6 | 32B | INT4 | — | ~500GB | — | — | ❌ **384GB 装不下** |
| GLM-5.2 / DeepSeek-V4 | — | — | — | — | — | — | ❌ 稀疏内核 sm_89 无 |

**三个关键发现:**

**① 无 NVLink 让"多副本"比"大 TP"更划算。** M2.7 走 **TP=4 ×2**:两副本是数据并行、零跨卡通信,把 PCIe 短板的影响降到最低,还白得一份冗余;而 TP=8 要 8 卡凑一个 all-reduce 组,在纯 PCIe 上损耗最大。

**② FP8 是 zc5s 的独有质量牌。** 同一个 M2.7,FP8(~230GB)质量明显优于 INT4,4090 能原生跑——这是 A40 上根本没有的选项。代价是 FP8 版单副本要 8 卡(TP=8),失去冗余。**质量优先选 FP8×1,稳健优先选 INT4×2。**

**③ 397B 在 zc5s 单机就能装下,不用跨机 PP。** 在 xt(A40)上 397B 得靠两台跨机 PP 才凑得下;zc5s 单机 384GB、INT4 ~200GB,**TP=8 一把梭**——省掉一整套 Ray 跨机 + 10GbE 调优的麻烦。唯一代价是 TP=8 全靠 PCIe。

## 五、推荐:MiniMax M2.7(两种布局二选一)

**为什么还是 M2.7**:和 xt 同理 —— 专为 agentic coding 调优(SWE-Pro 56%)、激活仅 10B、Lightning 混合注意力 KV 极便宜。在 zc5s 上它更从容(小、装得下),还能吃到 FP8 红利。

| 布局 | 量化 | 卡分配 | 优 | 劣 |
| ---- | ---- | ---- | ---- | ---- |
| **A. INT4 TP=4 ×2**(稳健,推荐默认) | INT4 | 卡0-3 / 卡4-7,两副本 | **有冗余** + 并发翻倍 + PCIe 友好(TP=4) | 质量略低于 FP8 |
| **B. FP8 TP=8 ×1**(质量优先) | FP8 | 8 卡一个副本 | **质量最好**(FP8 权重 + FP8 KV) | 无冗余 + TP=8 PCIe 通信重 |

> **建议**:先按 **A(INT4 TP=4 ×2)** 上线拿到冗余与吞吐;若实测发现质量吃紧、且 TP=8 的 PCIe 损耗可接受,再切 **B(FP8)** 换质量。两者前端都可挂 nginx/LiteLLM 统一入口。

### 次选:Qwen3.5-397B-A17B(要更强通用推理时)

INT4 ~200GB,**单机 TP=8 ×1** 装下。通用推理/长程规划明显强于 M2.7,17B 激活也不算高。代价:**单副本无冗余 + TP=8 纯 PCIe 通信打折**,进场务必压测单路 tok/s。若写代码是绝对主场景,M2.7 的速度 + 冗余大概率体验更好。

### 高吞吐 / 多模态备选:Qwen3.5-122B-A10B

INT4 ~68GB,可跑 **TP=2 ×4 副本**(PCIe 最友好、并发最高)或 FP8 TP=4 ×2。原生多模态。能力档低于 M2.7/397B,但胜在快、稳、副本多。

## 六、zc5s 特有注意事项(上线前必查)

| 项 | 说明 |
| ---- | ---- |
| **银河麒麟 V10 驱动栈** 🔴 | **第一道关**:国产 OS 上 NVIDIA 驱动 + CUDA + vLLM 能否装通(内核头文件/驱动版本常对不上)。先 `nvidia-smi` 认全 8 卡、跑个小模型验证整条栈,再谈大模型 |
| **PCIe 拓扑** ⭐ | `nvidia-smi topo -m`:确认 8 卡是否同 root、有无跨 NUMA;TP 组尽量挑同一 PCIe switch 下的卡,减少 all-reduce 绕路 |
| **FP8 用不用** | 装得下就优先 FP8(质量红利);要冗余就 INT4 ×2。别下 NVFP4(无 FP4 硬件) |
| **供电/散热** 🔴 | 8× 4090 单卡 ~350–450W → GPU 峰值 **~3–3.6kW**,加 CPU 近 4kW。确认 PSU(常需双电源)+ 机柜配电 + 8 卡风道(改版 48G 多为涡轮卡,风压要求高) |
| **存储** | 权重(115–230GB)务必落 **SSD**;确认容量(FP8/397B 更大) |
| **是否内网/离线** | 若与 kty5l 一样是内网环境,需联网机 build 镜像 → `docker save` → 离线 `docker load`(参考 kty5l 的离线流程) |
