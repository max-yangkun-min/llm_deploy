## 可能原因分析

### 1. GPU 资源问题（优先排查）

- **症状**：多进程执行器 Worker 进程初始化失败
- **可能原因**：
  - 8×A100 未全部正确识别
  - P2P 通信失败（拓扑问题）
  - CUDA_VISIBLE_DEVICES 配置错误

**排查命令**：
```bash
nvidia-smi
nvidia-smi topo -m
docker run --rm --gpus all nvidia/cuda:12.8.1-base-ubuntu22.04 nvidia-smi
```

### 2. 模型路径/挂载问题

- **症状**：EngineCore 初始化阶段失败
- **可能原因**：
  - `/model` 挂载点不正确
  - 权重文件缺失或损坏
  - `config.json` 文件有问题

**排查命令**：
```bash
docker exec glm52 ls -la /model
docker exec glm52 cat /model/config.json | head -20
```

### 3. CUDA/PyTorch 版本兼容性

- **镜像配置**：torch 2.11.0+cu128，原生 sm_80 扩展
- **可能问题**：
  - 宿主驱动版本不匹配（需 ≥570）
  - cu128 扩展与 sm_80 兼容性问题

**检查项**：
```bash
# 宿主机驱动版本
nvidia-smi | grep "Driver Version"

# 容器内 CUDA 版本
docker exec glm52 python -c "import torch; print(torch.version.cuda)"
```

### 4. PR #38476 补丁未生效

- **症状**：缺少必要的兜底日志
- **应该出现的日志**：
  ```
  [cuda.py] Using TRITON_MLA_SPARSE attention backend
  [sparse_attn_indexer.py] DeepGEMM not supported on this platform; using Triton fallback
  ```

**验证命令**：
```bash
docker logs glm52 2>&1 | grep -E "TRITON_MLA_SPARSE|DeepGEMM|Triton fallback"
```

## 排查步骤建议

### 第一阶段：GPU 和资源检查

```bash
# 1. 检查 GPU 状态
nvidia-smi
nvidia-smi topo -m

# 2. 检查驱动版本
cat /proc/driver/nvidia/version

# 3. 验证容器 GPU 访问
docker run --rm --gpus all nvidia/cuda:12.8.1-base-ubuntu22.04 nvidia-smi
```

### 第二阶段：容器和挂载检查

```bash
# 1. 检查容器状态
docker ps -a
docker inspect glm52 | grep -A 10 "Mounts"

# 2. 检查模型文件
ls -la /path/to/models/GLM-5.2-AWQ-INT4/
find /path/to/models/GLM-5.2-AWQ-INT4/ -name "*.incomplete" -o -name "*.lock" -o -name "*.part"

# 3. 检查日志
docker logs glm52 --tail 100
```

### 第三阶段：vLLM 配置验证

```bash
# 1. 检查环境变量
docker exec glm52 env | grep -E "CUDA|NCCL|VLLM"

# 2. 检查 PyTorch 和 CUDA
docker exec glm52 python -c "import torch; print(f'PyTorch: {torch.__version__}, CUDA: {torch.version.cuda}')"

# 3. 检查 vLLM 版本
docker exec glm52 python -c "import vllm; print(vllm.__version__)"
```

### 第四阶段：启用详细日志

```bash
# 重新启动容器，启用 NCCL 调试日志
NCCL_DEBUG=INFO ./start.sh start

# 或者检查现有日志中的详细错误
docker logs glm52 2>&1 | grep -E "ERROR|WARNING|Failed|failed" -A 5 -B 5
```

## 备选方案

### 方案 A：使用兼容模式启动

如果拓扑显示 `SYS` 或 P2P 通信有问题：

```bash
NCCL_P2P_DISABLE=1 ./start.sh start
```

### 方案 B：降低资源需求

```bash
GPU_DEVICES=0,1,2,3 MAX_MODEL_LEN=32768 MAX_NUM_SEQS=8 GPU_MEMORY_UTILIZATION=0.85 ./start.sh start
```

### 方案 C：检查镜像构建问题

如果以上都无效，可能需要重新构建镜像：

```bash
cd kty5l/build-glm52-vllm-cu128/
# 检查构建日志和验证脚本
```
